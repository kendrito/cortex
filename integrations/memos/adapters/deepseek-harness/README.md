# MemOS memory for Cortex

This private adapter loads `@cortex/memos-local-memory` through a Cortex profile. It keeps MemOS storage, embedding, viewer, recall, capture, reflection, policy induction, and skill evolution on the local host. Language-model work uses the selected Cortex provider and model; a cloud Cortex provider still receives those memory requests. The plugin accepts no separate memory provider, API key, endpoint, or fallback.

## Configuration

The bundle patch is [cordis.patch.yml](cordis.patch.yml). Its `home` defaults to `$CORTEX_HOME/memos-plugin`, or `~/.cortex/memos-plugin` when `CORTEX_HOME` is unset. `DSH_HOME` has no effect. Set MemOS `embedding.model` in that home's configuration to an absolute directory containing the preprovisioned local embedding model assets. Startup fails if those assets or the Cortex LLM service are unavailable. It never downloads models during memory use.

`hostLlmEnabled` must remain `true`. Privacy policy locks all auxiliary LLM clients to the Cortex host, disables telemetry and remote sharing, and keeps the viewer on `127.0.0.1`. Full memory evolution remains enabled. `recallEnabled`, `captureEnabled`, `toolsEnabled`, and `viewerEnabled` independently control the corresponding features. Viewer port defaults to `18801`. Startup failures throw by default; an explicit `failOnStartupError: false` allows Cortex to continue with the memory plugin stopped.

## Recall and capture

Every accepted nonempty direct-user turn receives one automatic recall, including restored and forked sessions. Recall uses at most `min(recallTimeoutMs, 3000)` milliseconds. The adapter appends bounded, source-labelled `<memos_context>` after accepted user messages and preserves the host's request-series declaration. Cortex persists that injected context with the model-visible messages. Recalled content is untrusted historical data, and plugin-generated messages cannot trigger recursive recall.

The six tools are `memos_search`, `memos_get`, `memos_timeline`, `memos_environment`, `memos_skill_list`, and `memos_skill_get`. They share the automatic capture and recall namespace: the configured profile or agent preset plus a hash of the complete normalized original project path in the immutable Session header. Equal directory names in different locations and sessions created in separate worktrees have different owners; successive sessions in the same project share memories. Switching an existing Session's working directory retains its original memory owner and records the latest durable directory in capture metadata. Sessions without an original project share a separate projectless namespace.

Structured session events feed a per-session queue. At turn end, capture and evolution use the completed request's provider/model pair. Foreground recall and tool operations use the live agent selection. Provider and model are always taken from one complete route; partial selections never combine with an older header or invoke a fallback provider. Async-local route storage keeps concurrent sessions independent. Auxiliary text and JSON requests can disable reasoning where the selected model advertises that capability; their provider and model remain unchanged.

Derived policies, world models, and skills keep the complete profile and workspace owner of their evidence. Association filters ownership before vector limits; induction buckets, world-model clusters, cooldowns, merges, and skill evidence do not combine private owners. Queued learning and delayed reward jobs capture their triggering event's async context, then restore its selected provider/model when executed. A job queued behind another session cannot inherit that session's model route.

Foreground recall failures leave the host's accepted input unchanged. Background capture failures are logged. When the agent becomes idle, the adapter claims Cortex's maintenance phase to commit queued capture, finalize reflection, and drain memory evolution before queued user work resumes. `agent.whenIdle()` follows that maintenance, so a headless run keeps its selected model available until memory work settles. The awaited `session/flush` checkpoint also drains completed work; checkpoints inside an active turn leave its memory episode open. Session and plugin disposal perform remaining cleanup. Autonomous recovery without an owning Cortex model route is disabled.

## Verification

The adapter tests under `tests/unit/adapters/deepseek-harness*.test.ts` cover route isolation, selected-model dispatch, recall ordering, request-series preservation, workspace ownership, capture queues, deadlines, disposal, tools, and viewer lifecycle. `tests/cortex` also exercises derived-evidence ownership, queued learning routes, and retrieval fallback. With `MEMOS_TEST_MODEL_DIR` pointing to preprovisioned assets, `tests/cortex/native-host.test.ts` drives production Cordis, AgentLoop, Session, and LLM services through automatic capture, reflection, restart, durable recalled context, native memory tools, and workspace isolation. Generation is deterministic; SQLite and semantic embeddings are real. The historical directory name identifies the upstream adapter; all runtime host dependencies are Cortex packages.
