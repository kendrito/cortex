# Testy in Cortex

This source is the Windows Testy runtime shipped with the Cortex Testy plugin. The original standalone Testy source and its personal workspace are separate. Cortex owns the packaged runtime, its private workspace, MCP connection, model routing and process lifetime.

The MCP catalog in `src/Testy.Cli/Mcp/CortexMcpTools.cs` extends the native inspection, action, test editing and run tools with suites, CSV materialization, demonstration recording and drafting, refinement, run explanations, project command settings, bounded queues, schedules, lifecycle preparation, Hyper-V operations, backup and restore. Long operations return a `taskId`; use `get_task` or `cancel_task`. Native `run_test` returns a `runId`, with `get_run` and `cancel_run`. Saved test revisions support optimistic update/delete through `expectedRevision`. Native `find_app` (model-visible, with the same Cortex metadata as `list_apps`) resolves an app named in words, and the native app tools, `launch_app`, `run_test` and `create_test`/`update_test`/`validate_test` accept `app` instead of `pid`, `exe` or `targetPath` (see [MCP.md](MCP.md#naming-the-app)); `update_test` keeps a test's stored app name when an editor sends back its unchanged `targetPath`.

`ai_test` accepts a natural-language testing request and discovers the app before drafting, saving and running a test through the same pinned Cortex model context. A saved `testId` skips drafting; `draftOnly` returns an editable unsaved plan. Manual `pid` and `exe` overrides are optional. Discovery sends a bounded inventory of visible applications and GUI executables found in the host-supplied `cortex/workspace` directory, plus the saved test target, to Cortex's configured model. It treats application titles as data, accepts only captured candidate IDs, rechecks process identity and executable bytes, and returns a clarification question without controlling an app when the target is ambiguous. It never invents executable paths or shell commands. Tasks expose discovery, drafting and execution progress; native Results retain the saved test, run and evidence. Auto-launched apps belong to the task and close when it finishes or stops. `launch_sample` opens one of the three bundled sample apps without a model call.

`draft_test` and `refine_test` use the same discovery when a target override is omitted. They return an unsaved draft and selected target, or the same clarification result. An optional inline `draft` carries current editor changes to the planner without saving them; a saved test also requires the editor's original `expectedRevision`, which is checked before model work. Refinement returns that original revision, and applying it still requires the normal optimistic save. A draft never executes its steps.

Integrated mode selects Cortex's model adapter regardless of provider fields in workspace files. Only the Cortex host holds actual provider credentials. Its authenticated loopback bridge accepts a host-issued context in `X-Testy-Cortex-Context`. MCP calls receive that context through `_meta["cortex/context"]`; it remains attached to their background work and owned Testy child processes. A queue pump binds the current Cortex context when it starts; queued definitions never save expiring contexts or credentials. Native Studio uses its Cortex-owned context and Cortex's current GUI model selection.

Workspace project commands and screenshot preferences require the authenticated human interface. The MCP tools advertise `cortex/humanOnly`, which Cortex enforces independently of discovery. Source access remains disabled until a user selects a project and fixed command catalog. Target applications receive a scrubbed Unicode environment from both native Windows launch paths; bridge tokens and contexts do not enter target processes. Integrated Studio hides independent provider configuration and blocks its alternate MCP listener, unmanaged workspace spawning and elevated background-agent installation. Queue processing remains available while Cortex owns the process.

Hyper-V AI uses the existing authenticated PowerShell Direct connection. The guest writes a bounded request into a private directory for its individual run; the host forwards it to the pinned Cortex loopback bridge and returns the correlated response through PowerShell Direct. The guest receives no host model token, provider key, endpoint or context. There is no network listener in the guest. Requests are sequential, capped at 16 MiB, and bounded by cancellation and deadlines. Guest prerequisites and existing guest credentials are still required; packaging does not provision a VM, elevate, or install an autostart service. Native Studio's Virtual machines tab can refresh inventory and save a guest sign-in in Windows Credential Manager without the standalone Agent; return to Cortex to prepare the VM and process its queue. These operations use the current Windows user's existing Hyper-V permissions. Local mailbox exchange, host routing, refusal and PowerShell syntax are covered by tests. Execution on a real Hyper-V guest requires a configured VM and remains a separate verification step.

Build the complete self-contained Windows x64 payload with:

```powershell
$env:CORTEX_DOTNET = 'C:\path\to\dotnet.exe'
.\native\testy\scripts\publish-cortex.ps1
```

Use .NET SDK 9 with the Windows desktop runtime packs. The script publishes CLI, Studio, Agent and all three sample applications, copies docs/examples and .NET notices, and seals the payload with SHA-256 hashes. Existing matching source and payload hashes allow a cached build without an SDK. `-Force` rebuilds; `-Output` must stay inside the Cortex repository. Source changes during publishing fail before replacing the previous runtime. No installer or service is run. A packaged Cortex must retain the entire runtime directory as adjacent physical files, including JSON, resources and Hyper-V scripts.

Tests use the copied source only. Run `Testy.Tests.dll` with the SDK host; `--only Cortex` covers integration and model boundaries. `scripts/check-cortex-relay.ps1` runs a loopback-only mock host bridge under Windows PowerShell 5.1. No test requires a paid model call or downloads a model.
